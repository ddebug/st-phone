# 单角色聊天记录导出 / 导入

入口：聊天页右上角菜单 → **聊天设置** → **聊天记录迁移**。

## 页面行为

- **导出聊天记录**：把当前角色（联系人）的聊天消息下载为 `acsus-chat-<角色名>-<时间>.json`。只包含消息，不包含联系人、记忆、回复预设、API 配置或其他角色。
- **导入聊天记录**：选择本功能导出的 JSON，合并到当前角色。不覆盖、不清空现有记录；相同消息 ID 自动跳过。
- 导入前会显示来源角色、总条数、预计新增和重复条数。文件角色与当前角色不同时会额外提示，但仍可导入当前角色。
- 导入完成后会刷新当前聊天页和消息列表预览；重复导入同一文件不会产生重复消息。
- 图片、表情等媒体仍只保留原文件引用，不随 JSON 打包；与原版整机备份的限制一致。

## 文件格式

```json
{
  "format": "acsus-phone-chat",
  "version": 1,
  "exportedAt": "2026-11-17T00:00:00.000Z",
  "character": { "id": "tavern_alice", "name": "Alice", "avatar": "alice.png" },
  "messageCount": 2,
  "messages": [ /* 原始 message 对象 */ ]
}
```

- 只接受 `format = acsus-phone-chat` 且 `version = 1` 的文件；整机备份、随机 JSON、其他备份格式会被拒绝并提示。
- 导入文件上限 32 MiB、消息上限 50,000 条；消息数量与 `messageCount` 不一致时拒绝。
- 消息只接受 JSON 普通对象；会剔除 `__proto__`、`prototype`、`constructor` 等原型污染键，并校验发送者、类型和时间。
- 缺少消息 ID 时，导出会生成稳定 ID；导入也会生成稳定 ID，便于重复导入去重。
- 合并按消息 ID 去重，再按消息时间稳定排序；同时间消息保持原有先后。

## 数据边界

不会修改：

- `contacts` 中的角色资料、头像、来源和备注。
- 记忆方案、LLM 方案、回复预设、API 接口、钱包和会员数据。
- 其他角色的聊天记录。
- 媒体实际文件。

## 验收结果

- `npm run check` 通过。
- 新增 `tests/chat-history-transfer.test.mjs`，覆盖创建、解析、格式拒绝、原型污染、去重、排序和无效参数；11 项通过。
- 合成宿主实测：导出 3 条消息；导入含 1 条新增消息的 JSON 后变为 4 条，重复 3 条跳过；重复导入显示“没有新增消息”，存储保持 4 条。
- 打开导入后聊天页立即显示新增消息。
